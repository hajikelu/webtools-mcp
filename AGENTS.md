# webtools-mcp

- Write code comments, commit messages, docs, issues, and PRs in English, even when the conversation is in Japanese. The exception is `README.ja.md`, the Japanese translation of `README.md`: write it in Japanese, and update it whenever `README.md` changes.
- mise provides Node.js and pnpm from `devEngines` in `package.json`. In a shell where mise isn't activated, prefix commands with `mise exec --` (for example `mise exec -- pnpm test`); otherwise the `devEngines` check rejects the Node.js on `PATH`. `pnpm update --latest --include-github-actions` updates every dependency and action in one run, across major versions, and keeps exact pins exact. It leaves `devEngines` alone: look up new versions with `mise latest node` and `mise latest pnpm`, edit `devEngines` by hand, and run `mise install`. Then run `pnpm audit`: GitHub's dependency graph can't read the two-document `pnpm-lock.yaml` that pnpm 12 writes, so Dependabot alerts miss every npm package. Skip `pnpm self-update` and `pnpm runtime set`, which install a second pnpm or Node.js beside mise's.
- Run everything through `cf` and the scaffold's `package.json` scripts. Keep Vite+ out: `vp migrate` swaps `vite` for a package without a `vite` binary, and `cf dev` and `cf build` stop working.
- Before every commit, run `pnpm fmt` (oxfmt), then `pnpm run check`, the checks CI runs.
- Unit tests (`node --test`) cover the auth module and `web_render`, which they hand a fake Browser Run binding: triggering Browser Run's failures for real bills browser time. Node runs these modules by stripping types: import with the `.ts` extension, and leave out Workers-only modules such as `cloudflare:workers`. Verify the other tools against a running Worker: `cf dev` connects the same remote bindings as production. Start `pnpm dev` (port 5173; it takes no arguments), then run `node scripts/mcp.ts tools/list` or `node scripts/mcp.ts web_fetch '{"url":"https://example.com/"}'`. Every tool call bills the account, `web_fetch` a little and `web_search` and `web_render` more: call those two only when the change touches them or the user asks.
- Pin `agents`, `@modelcontextprotocol/server`, `cf`, and `@cloudflare/vite-plugin` to exact versions. `agents` peers on one exact `@modelcontextprotocol/server` version, and its web adapters are `@beta`. After changing dependencies, run `pnpm peers check`: `pnpm install` only warns about unmet peers, and CI fails on them.
- Keep `allowBuilds` in `pnpm-workspace.yaml` as it is: install scripts run in the deploy job, next to the Cloudflare secrets. If a new dependency needs one, explain why in the PR and let the user decide.
- Keep the tool names `web_search` and `web_fetch`: the `agents` web adapters' descriptions, result headers, and error messages refer to them by name.
- Auth fails closed: verify the Access JWT's signature, issuer, and audience on every request. The auth bypass exists only in development mode, and `cf deploy --dry-run` must not list it.
- Keep the Cloudflare account ID and client MCP configs out of the repo.
- Workers Logs is on. Keep the `Cf-Access-Jwt-Assertion` header out of logs: it carries the user's email.
- Changes reach `main` only through a pull request; a ruleset enforces this. Work on a branch and open a PR.
- Merge with a merge commit when the PR's commits are split by meaning and each one passes `pnpm run check` (`git rebase main -x 'pnpm run check'`); squash otherwise. A squash commit gets the PR title and an empty body, so pass the body the merged commit needs (a measurement, a constraint, the reason for a choice) at merge time: `gh pr merge <n> --squash --body-file <file>`, or `--body-file <(git log -1 --no-show-signature --format=%b <commit>)` to reuse a branch commit's.
- Label a PR `trivial` when you can tell by reading, without running anything, that it breaks nothing and weakens no safeguard (typo and comment fixes, formatting, dropping a setting nothing uses). A change to the rules in this file is never trivial. `-label:trivial` hides these PRs from lists and searches; turn on auto-merge for them with `gh pr merge --auto` and the merge flags above. The user merges every other PR, unless they ask for auto-merge. Auto-merge takes whatever the branch holds once `check` passes: before pushing a change that isn't trivial to a `trivial` PR, remove the label and run `gh pr merge --disable-auto`.
- `.github/workflows/deploy.yaml` holds the Cloudflare secrets: keep it triggered only by pushes to `main`, so pull requests never reach them. Name workflow files `*.yaml`, and pin every action to a commit SHA: `pnpm update --include-github-actions` pins an action written with a tag and updates the pinned ones. The repository allows only `actions/checkout` and `jdx/mise-action`; a PR that adds another action must say so, so the user can extend the allowlist.
